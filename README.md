# Проект отказоустойчивой веб-инфраструктуры

Реализация отказоустойчивого кластера для веб-версии с балансировкой трафика и сквозным мониторингом.

---

## Технологии и архитектура

Для демонстрации инфраструктурных подходов был выбран **FastAPI (Python)**. Архитектура специально спроектирована так, чтобы показать методы масштабирования и обеспечения высокой доступности:

* **Бэкенд**: 3 независимые реплики приложения Python, запущенные в изолированных Docker-контейнеров. Python выбран намерено: его производительность на CPU-интенсивных задачах позволяет наглядно продемонстрировать утилизацию ресурсов хоста при сравнительно небольшом потоке запросов.
* **Балансировщик**: Nginx, распределяющий входящий трафик между репликами по алгоритму Round-Robin.
* **Мониторинг**: Prometheus (сбор метрик приложения) + Grafana (визуализация RPS, времени ответа и утилизации CPU/RAM).

## Точки входа (Endpoints)
1. `/` - базовый health-check, возвращает статус системы.
2. `/compute` - CPU-bound эндпоинт, выполняющий математические вычисления для имитации реальной бизнес-нагрузки.

## Управление проектом через Docker

### Локальный запуск одиночного контейнера (для тестов):
```bash

# Сборка образа
docker build -t sre-app .

# Запуск контейнера
docker run -d -p 8080:8080 --name web-app sre-app

# Удаление контейнера
docker rm -f web-app
```

### Запуск всего отказоустойчивого кластера (Nginx + 3 приложения + Мониторинг):
В корневой директории проекта, где находится файл `docker-compose.yml`, выполните:
```bash
docker-compose up -d --build
``` 

## Нагрузочное тестировние
Для проверки отказоустойчивости системы проводился стресс-тест с помощью утилиты Apache Benchmark (`ab -n 10000 -c 50`).

**Сценарий симуляции аварии:**
1. Запускается интенсивный поток запросов на балансировщик Nginx.
2. Прямо во время теста принудительно останавливается одна из реплик:
```bash
docker stop sre_project-app1-1
```
3. **Результат:** Nginx мгновенно фиксирует падение контейнера `app1` и бесшовно перенаправляет весь трафик на выжившие `app2` и `app3`. Конечные пользователи не получают ошибок, а в Grafana фиксируется перераспределение графиков RPS.
